# S115 records — what was rescued off the session scratchpad, and what was not

**Greg, S115 close: "whatever is on scratchpad needs to be committed to a file in git so we don't
lose whatever is on it... and we're not supposed to be using scratchpad anymore."**

Both halves are right, and the second is D33/D34 — **there is nothing local; git = code and records,
S3 = data, `data/` is disposable.** The harness offers a session scratchpad and I used it for working
files anyway. This directory is the repair; **D52 is the rule that stops it recurring.**

Everything here is content that **cannot be regenerated by re-running a command**. The regenerable
material is listed at the bottom and was deliberately NOT copied — declared, not silently dropped.

paid for"; these IDs are how you honour that if the phantom tree is ever lost.

**Read the destination strings literally: `data/nymex_cont_n0` is what the log PRINTED, and it is the

whole of M-16, and these four files are the primary record of it.

**Two of the four are the `.v.0` basis.** The walk is built on `.n.0`; `.v.0` whipsaws through expiry
weeks (S97). If anything is ever decoded from `NEK78EWGLK` or `Y65VR393GC`, it is the WRONG LEG for

## 2. `refine_g24_aborted/` — the g24 refine that was started and stopped

The g24 refine reached **2 of 10 posteriors and was stopped**; both posteriors were discarded as
artifacts of the degraded brain view (the field cut described in the S115 handoff, since reverted).
The posteriors are gone on purpose. **The inputs are kept, because they are authored content and the
next attempt should start from them rather than re-derive them.**

- `directive.txt` — the round-1 refine directive. Its thesis is the one that still stands:
  **magnitude is the target, not direction.** g24 blind was 6/10 direction (its best of the walk) at
  **0.29x of realized magnitude, under on 8 of 10 days**, so a refine returning 10/10 direction at
  the same sizing has fixed nothing. It also carries the derived-not-fitted bar and the
  sum-the-live-drivers instruction.
- `spawn_render_C_g24_r1.txt` — the actual rendered specialist prompt served to C. Reproducible from
  `spawn.py` in principle; kept because it is the exact bytes a specialist was given, and a render
  and its inputs can drift.
- `preinfluence_C_20260721.txt`, `preinfluence_D_20260723.txt`, `E_0722_preinfluence.txt` — the
  pre-influence records for the three lenses that got that far.

**Do not treat any of this as a scored round.** No posterior here survived, nothing was archived, and
the line correctly shows g24 as `blind-scored -> archived`, never `refined-r1`.

## 5. THE RULE THAT COMES OUT OF THIS — D52

**Nothing authored may live only on a session scratchpad.** The harness offers one and will keep
offering one; that is not permission. If a tool forces a temp path, the artifact is copied into git
**before session end and verified by reading the committed copy back** — not by trusting the copy
command's exit code, which is the NC-3 shape this repo has now seen four times.

`plant_status.py`'s scratchpad gate catches a **handoff that NAMES a scratchpad path**. It does not
and cannot catch **work that merely sat on one**. This directory exists because the second failure
mode has no automatic detector, so it needs a habit and a decision line instead.
