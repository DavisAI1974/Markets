## Follow-up: fees, execution assumptions and crypto isolation

The pinned standalone NG path computes market-channel statistics. Tracing its imports and loader calls found no execution-cost calculation, crypto bins or crypto-era trade rules in that path. It reuses the numerical estimators and leakage utilities in odcore. Runner source, CLI text and JSON metadata still mention cost, including `trade_cost_in_any_calculation: false` (`markets_bridge/ng_runner.py:255,364,436`). The full repository therefore fails a literal removal check.

- `research/kalshi/level_hit_dataset.py:230-234,427` still subtracts `entry_slip` from reported `net_cents` and defaults the offset to 1 cent. An isolated function check on the same path returned `net_cents=1.0` with offset zero and `0.0` with offset one. `continued`, `run_length` and `resolution` were identical, and reported fees were zero.
- `research/kalshi/lag_exploit_backtest.py:56-72,141-148,218` still deducts a modeled toll from derived outputs. The fee helper returns zero. With an observed spread of 4 cents, the existing function returned a 2 cent maker toll and 4 cent taker toll. Observing the spread is distinct from subtracting it as an assumed execution cost.
- `research/kalshi/lag_join.py:87-97,361,413` retains the unused fee formula and advertises old execution arguments that no longer affect the result. An isolated check at 50 cents returned zero for the active fee helper and two for the legacy formula. `research/kalshi/coach_replay.py:35,66-79` still subtracts a zero fee constant and publishes outputs named net. Active docstrings and CLI help still carry stale fee language.
- `scripts/session_start.sh:19-46` retains the materializer. Default startup bypasses it, and setting `KALSHI_MATERIALIZE_CRYPTO_BINS=1` enables the old fetch and writes `realbins/` when the directory is absent or empty. The flag was unset or inactive in the audited process. There were no local root or data `realbins` directories, and the legacy BTC, ETH and perpetual-history refs remain in Git. The hook was inspected without running it.

Keep prior receipts and the frozen snapshot as historical evidence. If the removal standard applies to active shared Kalshi code, remove or version the residual execution deductions and output fields, update active help, and remove the crypto opt-in from the active startup hook.
