# ROOT and Native efficiency audit

The code paths audited are the ROOT orchestration at `db96f24f`, its legacy book adapter at `af36937d`, and the Native producer checkout at `2ebb8ce8`. The two book adapter blobs are different. Exact Git objects were used to check behavior before considering reuse. This audit concerns the producer stage ahead of SQLite and Julia.

## Measured book-kernel changes

The [benchmark receipt](root-native-efficiency-benchmark.json) covers the first 1,600 NGX3 tape records from each of the October 3 and 18 UTC files. An untimed pass checks the ordered frame, ROOT full-book and legacy JSON digests. Every candidate matched its producer's baseline across 1,488 frames. Timed passes perform the same book work without the comparison encoding. Run `python -B -m research.kalshi.adaptive_wavepacket_20261108.markets_bridge.benchmark_root_native_efficiency --records 1600` from the repository root. `--stage-patches` writes the checked candidate diffs to a fresh directory. The measured scope is the in-process adapter and capture path. It excludes full ROOT packing, the Native lifecycle driver, IPC, checkpoints, projection and disk I/O.

- The level builder sorts the same queue-age list separately for the median and p90, then repeats the age calculation when emitting individual FIFO rows. The candidate sorts once and uses the original unsorted per-order ages for FIFO, with the same interpolation, float arithmetic, ordering and nulls. A separate initial ROOT run over 7,000 messages and 4,660 full frames matched the entire ordered output hash. Median time was 13.4468 seconds before and 10.8694 after, a 19.2% reduction for the measured path.
- ROOT's top-ten legacy signatures and control rows already read only price, quantity and order count. Native's older base adapter still builds entire top-ten summaries, including ages and concentration, for those legacy views. Its summary backport alone reduced the median from 5.0249 to 4.5551 seconds. The backport uses the newer base adapter, which also avoids eager book construction in the base `apply` method that FullCapture overrides.
- Native FullCapture constructs a default instrument book eagerly, even for an already-open instrument. Reusing its live book moved the median by 0.5%, within the observed run variation. The Native candidate keeps the current FullCapture method.

## Repeated work in the stage

| Priority | Observed path | Repeat strategy and verification |
| --- | --- | --- |
| 1 | ROOT defaults to replica frame shards. The main replay and each shard decode and apply the same input records from the fork boundary. Shards divide the full frame rows by ordinal. The duplicate decoding/book updates grow with shard count even when the repeated reads hit page cache. | Benchmark the default against `FRANKIE_ROOT_LEGACY_FRAME_SHARDS=off` on the same Linux lane and prefix. The alternate route uses one ordered ROOT replay, dirty-level book mirrors and ordered pure encoding workers. Compare output bytes, save/resume and worker-loss behavior, elapsed time, CPU-seconds, IPC and reads. Keep Native's separate stateful traversal and pin until actual producer parity demonstrates a shared state interface. |
| 2 | ROOT copies and sorts the complete observation at each close alongside the full FIFO book, then packs the nested row. The full-depth snapshot also computes its top ranks again even when a consumer takes only the full lists. | Reuse immutable level results within one close while keeping required top/full output representations independent. Investigate the existing `IncrementalObservation` fragment code for exact ROOT packing. Validate the complete output bytes at resets, equal receive times and replay/checkpoint boundaries. Separate verified optimization from any change to serialized format. |
| 3 | Native finishes a run with `span_seconds(records)`, which iterates and decodes the source spool again just for receive min/max. On a valid full-state resume, `consume_recovery` consumes the already-checkpointed prefix through the decoding iterator before starting new records. | Compute the same nullable integer min/max while witnessing the spool and retain it under the exact source identity. For full-state resume, use a validated record-to-byte checkpoint index to seek. Keep the original reconstruction route when state is missing or a source/offset witness fails. Test older checkpoints, interrupted saves, changed prefixes and identical suffix results. |
| 4 | Projection writes and hashes compressed range fragments, then publishes compressed layers. Publication computes a whole-file SHA-256 from a separate post-close read. The source-check path can also read large spools twice when the independent hasher and range decoders walk the same file. | Measure actual physical and logical bytes first. Bind digests to write/read streams where the contract allows it, and keep an independent readback at the appropriate publication boundary. Preserve exact fragment verification, fsync, identity and count gates. Use producer claims only while their source, stat and tail conditions hold. |
| 5 | Native enriches and then removes the base adapter's fixed-window `activity` block. The published Native features use event-anchored activity. The base rolling call also updates internal state. | Treat the emitted allocation as a candidate, with a separate checkpoint and window-expiry test before changing it. ROOT still publishes the fixed-window block. Never collapse the two definitions or remove observations. |

The existing code already has one-pass witness/count routes, reusable sealed claims, an exact fallback for changed files, a write-stream checkpoint hash, bounded ordered worker queues and pipelined Native replenishment. Preserve those mechanisms. Existing source-level dedupe does not by itself establish which mode is fastest on the next host. The optional Markdown digest is a presentation/knowledge consumer decision, separate from the market ledgers. Determine its real consumers before skipping or rendering it later.

## Before sizing compute

The original five ROOT and Native carriers total 699,127,966,488 bytes for October 18, including 496,743,568,399 bytes of ROOT frames and 193,743,650,444 bytes of Native members. The 1,667 retained early ROOT frames occupy 107,111,996 compressed bytes and 1,062,179,166 uncompressed bytes. Those sizes describe that slice. They do not establish the compression ratio or scratch peak for an entire date.

Use the first bounded producer-to-SQLite run to separate measured throughput, CPU-seconds, peak RAM, peak scratch and lossless durable output. Include a normal book, a dense book, a reset and an exact stop/resume. Reconcile full records, depth, FIFO, lineage, formula values and output order. Reuse the already checked tape, trade-clock, external and absorption receipts. This is the remaining stage benchmark before choosing a box.
