# Guide task preparation and bounded change review

The authorized next Guide increments are implemented on free/Guide base `953bf3737425fc89c69f2daca5e744d8865886fd`: prepare a reviewed task from a piece/function and compare later local source changes with its agreed snapshot. The complete free map, goals and basic briefs are retained. This is a development preview with no billing/access enforcement or paid launch.

## Concrete workflow

1. Open Guide and prepare a task for the whole piece or a current function. Enter a goal, acceptance criteria (one per line), exclusions, optional related goal and explicitly selected support pieces.
2. Review exact allowed files, source identities, function/goal context and possible downstream source/planned dependency impact. Function focus never silently reduces or expands the disclosed file scope. Missing exact paths can be planned; new arbitrary paths require an existing explicit piece declaration. Invalid/missing/overlapping/unsafe scope and stale function/goal choices are refused.
3. Agree to the still-matching snapshot, then copy the detailed brief or select its manual text. Failed refresh or changed snapshot blocks agreement and automatic copy from old context. Stale/detached controls cannot act on another rendered task. The brief asks for current inspection, bounded changes, actual acceptance checks and preservation of evidence/goal/ownership contracts.
4. Keep working elsewhere in the map, then reopen **Guide task**. The agreed baseline is retained. Draft wording, support ids, focused input and text selection survive refresh. A single task stays in this tab; starting another replaces it and closing/reloading loses it. Copy the brief for your handoff. No task is automatically sent or written to project/evidence files.
5. Review later changes after a successful local read, including waiting for any in-progress refresh. Report inside/outside mapped file changes, file arrival/deletion or changed mapping, piece definitions/ownership, relationship/intent changes, evidence records/assessments, goals and separate completion. Inspect current target evidence and the next goal point, then actually check the criteria yourself.

Captured exports retain this same client and can prepare/copy a clearly captured task with manual fallback. They cannot compare a current working tree. GitHub clone snapshots, failed reads and different project/checkout identities also refuse current comparison. An earlier comparison is labeled out of date after another edit. The original agreed baseline is never silently replaced by later source or receipts.

## Exact review boundary

Comparison uses mapped implementation hashes, declared missing paths and the current hashes of explicitly assessed receipt inputs. It covers two observed snapshots, not every repository file, a line-level Git diff, semantic correctness or attribution to a particular agent. Mapped ownership/definitions remain visible independently of source content; source/planned dependency reachability suggests possible review scope and tolerates cycles. It does not establish actual runtime effects.

Acceptance criteria remain user-authored requirements, not an automated verdict. New/changed records and hash matches do not prove a task succeeded. The task/report never promotes piece states, outcomes or completion, authenticates observations or executes mapped source. Existing evidence freshness and goal/completion assessment remain independent.

`public/guide-tasks.js` is the pure capture/comparison/brief helper, assigned to the existing visualizer. `src/server.js` serves only its fixed public module route, and `src/export.js.clientSource()` bundles that owned module with the existing client for self-contained exports and DOM checks. No new runtime dependency, write API, agent transport or separate coding agent was added. The new task test file belongs to the existing verification piece. Its direct source import of the visualizer helper creates a real supported source dependency; the verification plan explicitly adds visualizer while retaining its prior dependencies, rather than suppressing the detected drift. Piece ids, previous ownership, goal steps and the free completion declaration are retained.
