## Bounded source fixes implemented

1. **One ordered range walk for FINALIZE materialization.** Scientific
   `_finalize_rows` previously checked every selected ordinal interval against every
   ledger row. It now advances once through the existing ordered inclusive ranges,
   preserving ledger order, original row contents, section order and complete byte
   hashing. Valid producer selections have identical membership. Malformed,
   overlapping, out-of-order or beyond-end selections refuse instead of being coerced
   or silently incomplete. No row is placed on a live axis and no numerical method changes.
   This removes repeated interval comparisons; no measured speedup is claimed.
2. **Accurate new-result accounting.** Ordinary `teach_accumulated` now reports
   `new_result_files` from its existing `created_files` counter, as the successor path
   already did. Exact completed-file reuse remains in `files` for publication and is
   counted separately by additive `completed_result_files`. `all_reused` now follows
   whether any result was created. Claim selection, result bytes, publication and
   scientific arithmetic are unchanged. No other Python consumer of these scope
   fields was found by source search.
3. Corrected the completed-native reader's docstring: its callers carry references;
   that interface must not describe the source rows as consumed by both seats.
