### 1. OD coin coeff-gen — CHUNKED PARALLEL DRIVER (BUILT in S27)
**Built as a Workflow in `_run_top20_bottom20_pairs.py`** — deterministic, resumable, parallelized, observable. The slowdown fix from the S26 root-cause analysis:

#### Architecture (S27 implementation)
- **24 buckets run in PARALLEL** (btc/eth x 3 venues x buy/sell x win/lose), each bucket as an independent worker via `ProcessPoolExecutor`. No cross-bucket contamination — each bucket writes to its own per-domain evidence graph file (`<domain>_evidence.json`). `index.json` tolerates concurrent last-writer-wins races (rebuildable). `--workers N` controls concurrency (default: CPU count, capped at 24).
- **100-trade batches** per bucket: each worker runs `arch_workflow.py --limit 100 --resume` in a loop until no trades remain. Back-to-back batches, fully automatic.
- **Archive-before-clear** (3-KB policy): after each 100-trade batch, the evidence graph is archived as `evidence_snapshot_batch_NNN_<ts>.json` (with metadata: domain, node/edge counts, timestamp) to ALL 3 knowledge bases:
  1. **OD KB** — `E:\refrag\discoveries\evidence_snapshots\`
  2. **Refrag KB** — `E:\refrag\docs\evidence_snapshots\`
  3. **Factory KB** — `F:\Factory\knowledge\evidence_snapshots\`
  Then clear ONLY that bucket's `<domain>_evidence.json` (never `*` glob — that would wipe sibling buckets mid-run) to reset per-trade cost to ~2.3 s.
- **Per-bucket output dirs** (`<base_out_dir>/<domain>/summary.json`) so parallel workers don't stomp on the same summary.json.
- **Background-safe**: logs per-batch to `_pipeline_logs/_bucket_<pair>_<outcome>_batch<NNN>.log`.
- **Resume-safe**: `--resume` skips already-done trades by source_id in summary.json.

#### Usage
```
python _run_top20_bottom20_pairs.py --pre-entry --cross-section --target-size 1075 --batch-size 100
```
