# Deployment notes

## HTTPS (required for the PWA + Web Push)

`Caddyfile` in this directory is the Caddy reverse-proxy + auto-HTTPS
config. It fronts the React PWA (built into `frontend/dist`) and the
FastAPI backend (uvicorn on `127.0.0.1:8080`), and handles Let's Encrypt
cert lifecycle automatically.

### Why HTTPS is non-optional

- **Service workers** only register on HTTPS in production browsers
  (Chrome, Safari, Firefox). Without HTTPS the offline cache + push
  notification path do not work.
- **Web Push** requires HTTPS end-to-end.
- **iOS Add-to-Home-Screen** requires HTTPS for the install prompt to
  show the app as standalone.

### Setup checklist (one-time, on the deployment host)

1. Install Caddy: <https://caddyserver.com/docs/install>
2. Edit `Caddyfile` — replace `markets.example.com` with your real
   hostname; ensure DNS A/AAAA points at this host.
3. Symlink: `sudo ln -s $(pwd)/Caddyfile /etc/caddy/Caddyfile` (or copy)
4. Build the frontend:
   ```bash
   cd frontend
   npm install
   npm run build
   sudo mkdir -p /var/www/markets-watch
   sudo cp -r dist/* /var/www/markets-watch/
   ```
5. Generate VAPID keys and set env:
   ```bash
   python -m backend.push --generate-keys
   # copy private + public into your backend env file
   ```
6. Run the backend (suggest a `systemd` service):
   ```bash
   uvicorn backend.api_server:app --host 127.0.0.1 --port 8080
   ```
7. Start Caddy: `sudo systemctl enable --now caddy`
8. Verify:
   - `curl https://markets.example.com/api/health` returns 200
   - PWA loads in mobile Safari/Chrome
   - "Notify me on new signals" button in Onboarding successfully
     subscribes (check `backend/push_subs.json` grew by one entry)

### Required environment variables on the backend process

| variable | purpose |
|---|---|
| `MARKETS_WATCH_ACCESS_TOKEN` | shared bearer token for `/api/*` (except `/api/health`); leave unset only in dev |
| `VAPID_PRIVATE_KEY` | generated by `python -m backend.push --generate-keys`; required for push to actually send |
| `VAPID_PUBLIC_KEY` | same; frontend fetches via `/api/push/vapid-public-key` |
| `VAPID_CONTACT_EMAIL` | `mailto:you@example.com`, required by Web Push spec |
| `DISCORD_BOT_TOKEN` | optional; only needed if running `discord_bot/signal_poster.py` |
| `DISCORD_CHANNEL_ID` | optional; same |

## Adding the PWA to a phone

After HTTPS is live:

- **Android (Chrome)**: open the URL → menu → "Install app". A native-
  feeling install prompt appears; once installed it shows up in the app
  drawer with the icon and runs in standalone mode (no browser chrome).
- **iOS (Safari)**: open the URL → Share → "Add to Home Screen". Must
  be done from Safari (Chrome on iOS won't trigger the standalone
  install). Once installed, push notifications work after granting the
  permission prompt the first time you tap the in-app "Notify me" button.

## Trade-bot deployment (optional; per-user)

The trade bot (`executor/executor.py`) runs on each user's own machine,
not on the central host. Each user clones the repo, edits
`my_config.json`, and runs:

```bash
python -m executor.executor --config my_config.json [--dry-run]
```

This keeps API keys + capital with the user. The central host only
distributes signals via the SSE stream + Web Push + Discord channel.
