## GitHub Actions

The repository already uses a standard GitHub Actions runner to perform compact ingest and upload the sealed result to external storage. It uses other GitHub Actions workflows to control compute boxes. The historical runner ingest script reads S3 archive manifests. The new Git-bound manifests require local staging of their verified Git DBN members before invoking the same ingest producer. [Runner ingest entry point](https://github.com/DavisAI1974/Markets/blob/db96f24f3260bf0d70c763b297c2ba9b84f571a6/deploy/aws/box/frankie_runner_ingest.sh#L1) · [Fleet workflow](https://github.com/DavisAI1974/Markets/blob/db96f24f3260bf0d70c763b297c2ba9b84f571a6/.github/workflows/frankie_fleet.yml#L67)

The standard x64 Ubuntu runner provides at most four vCPUs and 16 GB RAM, with 14 GB SSD. The current Native lane requires eight distinct cores, or sixteen for the current ROOT and Native overlap. Native projection independently requires a 20 GiB free-space reserve. The historical matrix and fitting footprint also exceed the standard runner limits. Compression reduces producer storage, so retain it on appropriately sized Linux scratch. [Standard runner limits](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) · [Projection reserve](https://github.com/DavisAI1974/Markets/blob/db96f24f3260bf0d70c763b297c2ba9b84f571a6/deploy/aws/box/frankie_box_projection.py#L314) · [Verified compression](../../research/kalshi/adaptive_wavepacket_20261108/markets_bridge/tasks/root-bounded-replay/compressed-scratch.md)

GitHub Actions can dispatch the three dates to suitable self-hosted Linux runners. GitHub's larger hosted runners are an organization or enterprise feature on eligible plans. For an eligible hosted runner, confirm the distinct core topology and compressed scratch peaks, then split stages around the six-hour hosted-job limit and place recoverable checkpoints in durable storage. The current repository owner is a personal account. Self-hosted execution can retain the sealed input, spools and checkpoints on its working volume between jobs.
